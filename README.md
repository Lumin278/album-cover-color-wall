# 专辑封面色墙 · album-cover-color-wall

把本地专辑封面按颜色拼成 N×N 的墙。选片决定用哪些图，排序决定怎么摆。

一个本地跑的 CLI 工具，输入一整个封面文件夹，输出一张同色系的方形拼图。
不需要联网、不上传图片、不需要 Spotify/网易云 API。

```
┌────┬────┬────┬────┐
│ 01 │ 02 │ 03 │ 04 │   同一色系
├────┼────┼────┼────┤   同一明度走向
│ 05 │ 06 │ 07 │ 08 │   相邻格子色差最小
├────┼────┼────┼────┤
│ 09 │ 10 │ 11 │ 12 │   底部标编号和专辑名
├────┼────┼────┼────┤
│ 13 │ 14 │ 15 │ 16 │
└────┴────┴────┴────┘
```

## 它跟其他拼图工具的区别

| | 常见做法 | 这个项目 |
|---|---|---|
| 版式 | 整个库排成一大面墙 | 按色系切出 N×N 的小墙 |
| 颜色空间 | RGB / HSV | **CIE Lab**（感知均匀） |
| 排序依据 | 色相、播放次数 | 色相 + **你自己的歌手亲和度** |
| 相邻优化 | 按一维序号 | **2D 网格邻接**（4→5 是换行，网格里不相邻） |
| 色池 | 固定阈值 | **严格核心色 + 分级自动放宽**，放宽级别写进报告 |
| 去重 | 只看哈希 | 哈希 + Lab 色距 + 灰度结构，防纯色封面误杀 |

## 三种选片模式

| 模式 | 做什么 | 适合 |
|---|---|---|
| `fav` | 色池内按歌手亲和度排序，同一歌手只留一张，不足按相似色补位 | 「这 16 张都是我常听的歌手」 |
| `similar` | 取离色池中心 Lab 距离最近的 N² 张 | 「一眼看过去颜色尽量接近」 |
| `gradient` | N² 个明度锚点做代价矩阵，匈牙利算法全局最优分配 | 「想有从上到下的明暗过渡」 |

实测同一批素材：相似色模式的色彩统一度比喜爱模式低一半以上（越接近池中心越统一），
代价是明度跨度小、没有渐变感。喜爱模式颜色散，是按亲和度选片的必然结果。

## 九种颜色

红 / 黄 / 绿 / 蓝 / 紫 / 橙 / 青 / 粉（品红）/ **黑**

每色有一套**严格核心阈值**，不够再分级放宽：

| 色系 | 严格核心 | 每级放宽 |
|---|---|---|
| 红 | h 15–45，C ≥ 30 | 色相 ±8°，C −4 |
| 黄 | h 85–115，C ≥ 25 | 色相 ±7°，C −4 |
| 绿 | h 115–165，C ≥ 21 | 色相 ±8°，C −4 |
| 蓝 | h 255–300，C ≥ 27 | 色相 ±8°，C −4 |
| 紫 | h 285–315，C ≥ 28 | 色相 ±5°，C −3 |
| 橙 | h 52–72，C ≥ 35 | 色相 ±6°，C −4 |
| 青 | h 188–212，C ≥ 27 | 色相 ±8°，C −4 |
| 粉 | h 335–5，C ≥ 25 | 只向紫侧放宽；红侧累计最多 +5° |
| 黑 | L ≤ 28 且 C ≤ 40 | L +2，C +5 |

池子的目标不是刚好凑够 N²，而是留出余量：

```
target = N² + max(8, ceil(N² / 2))     # 4×4 → 24 张
```

余量够了，相似色和渐变模式才有选择空间。放宽最多 4 级，4 级后仍不够才停下来问人。

**放宽是可见的**：报告里给出 `core_pool`（严格池）、`pool`（最终池）、
`relax_level`（放宽几级）、`effective_rule`（本次真实生效的阈值）。
同一张图在不同图库、不同尺寸下可能用不同阈值，`effective_rule` 是唯一可信的口径。

## 喜爱排序怎么来

这是本项目最不「自动化」的一环，因为它不该自动化。

**歌手歌曲数只是亲和度代理值，不等于你对某张专辑的评价。**

跑喜爱模式前，先确认喜爱依据：

| 你有什么 | 怎么用 |
|---|---|
| 歌单文本（每行 `歌名 - 歌手`） | `build_favourites.py --playlist` 统计每位歌手出现在多少首唯一歌曲里 |
| 已有的歌手排名 JSON | 直接 `--artist-ranks` |
| 只是能报出几个名字 | `build_favourites.py --artists "A,B,C"` 按给出的顺序排 |
| 什么都没有 | **不做喜爱模式**，改用 `similar` 或 `gradient` |

合作曲（`歌手 A / 歌手 B`）每位各计 1 次。歌名+歌手集合去重，同一首歌在多份歌单里重复出现只算一次。

```bash
python scripts/build_favourites.py --playlist playlist.txt --out artist-ranks.json
```

选片时每张专辑取 `artist` 字段里**排名最靠前的歌手**作为亲和度，按亲和度升序取前 N²。
不做「先按歌手白名单预过滤」——最爱的歌手在某个颜色里可能只有三五张，预过滤会直接凑不满。

## 快速开始

需要 Python 3.9+、Pillow ≥ 9.1、numpy。**不需要 scipy 或 sklearn。**

```bash
# 0. 先自测（用合成图，不碰你的图库）
python scripts/selftest.py

# 1. 喜爱歌手排名（可选，只有喜爱模式需要）
python scripts/build_favourites.py --playlist playlist.txt --out artist-ranks.json

# 2. 建索引：扫描封面目录，算每张的主色和干净度
python scripts/build_index.py --src ~/Music/covers --out index.json
#    文件名有歧义时加规则：
#    --filename-regex "^(?P<artist>.*?)_(?P<album>.+)$"

# 3. 去重
python scripts/dedupe.py --index index.json --out dedup.json

# 4. 出墙
python scripts/make_wall.py --index index.json --dedup dedup.json \
  --artist-ranks artist-ranks.json \
  --color red --mode similar --size 4 \
  --out red-wall.jpg --json red-wall.json
```

### 封面文件命名

默认解析 `编号_歌手_专辑.ext`。推荐直接把文件命名成 `歌手_专辑.jpg`，
这样在文件管理器里按名称排序时同歌手的封面会聚在一起，也方便脚本匹配。

有歧义（专辑名自带下划线、歌手名带分隔符）时用 `--filename-regex` 指定命名组，
必须包含 `album`，`artist` 可选。

## 算法

### 取主色

1. 封面缩到 96×96（快且够用）
2. median cut 量化成 7 色
3. 按像素占比加权平均
4. sRGB → XYZ → CIE Lab (D65) → LCh

不用「最大色块」是因为封面常有纯色边框和大面积留白，最大色块往往是背景而不是这张封面给人的颜色印象。

### 干净度

```
clean = 目标色带像素占比 − 0.9×对立色占比 − 0.7×过曝白占比
```

压制「色系对但画面杂」的封面。相似色模式裸跑时，画面里的绿色圆形、蓝色海面、
黄色大字都会破坏统一感，但它们的平均色离池中心很近——平均色看不到画面内部。

`--min-clean 0.25` 打开硬筛，池子会缩到一半左右，观感明显更干净。

### 内部排序

- 2D 网格邻接，横竖 48 条边（4×4），**不是** 1D 序列
- 主轴 `L + 0.25×C`（饱和色显亮），亮 → 暗
- 行内左→右不增、列内上→下不增
- 只在**不破坏单调约束**的前提下做同列上下互换
- 报告必须 `monotone: true`，否则停止出图

### 去重

同一张封面常被多张专辑共用（占位图、不同版本、双碟）。五条判据全过才算重复：

| 判据 | 阈值 |
|---|---|
| MD5 | 完全相同 |
| pHash 汉明距离 | ≤ 6 |
| Lab 平均色距离 | ≤ 12 |
| 灰度结构相关系数 | ≥ 0.92 |
| 灰度平均绝对误差 | ≤ 0.08 |

**颜色距离这条不能省**：纯色封面（整块同色）的 pHash 几乎完全一样，
只按哈希去重会把深浅不同的红封面全部判成重复。

## 参数

| 参数 | 作用 |
|---|---|
| `--color` | 红/黄/绿/蓝/紫/橙/青/粉/黑，或 `--hue LO-HI` 自定义 |
| `--mode` | `fav` / `similar` / `gradient` |
| `--size` | N×N 的 N，1–10，默认 4 |
| `--cell` | 每格像素，96–1600，默认 400 |
| `--artist-ranks` | 歌手亲和度排名 JSON |
| `--relax N` | 手动指定放宽级别，并关闭自动放宽 |
| `--no-auto-relax` | 只用严格核心色 |
| `--min-clean 0.25` | 干净度硬筛（仅预定义色相颜色，黑色和 `--hue` 不支持） |
| `--cmin` | 自定义彩度下限 |
| `--skip` | 专辑名黑名单 JSON |

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 参数错误 |
| 3 | 色池不足，需要问用户 |
| 4 | 文件、JSON、元数据或喜爱依据错误 |

成功时每个脚本都输出一行 JSON，方便管道和自动化调用。

## 已知局限

1. **歌手歌曲数只是亲和度代理**，不等于单张专辑的质量或偏好。
2. **极端黑底白字封面**的平均 L 会偏向中灰，这是平均色的固有偏差。
   剔除近白近黑或改用中位数实测都更差（暗封面反而变亮）。
3. `disp`（色散）对风景类封面不可靠，只作参考。
4. 喜爱模式会牺牲排序平滑度，2D 能量比相似色模式高数倍。
5. 单色系素材未必能形成连续渐变，素材足够散时渐变有上限。
6. 黑色规则是 L/C 阈值，仍可能混入少量深色彩色封面。
7. 自动放宽会让同一颜色在不同图库下用不同阈值，**以报告里的 `effective_rule` 为准**。
8. 文件名自动拆分有歧义时，用 `--filename-regex`。

## 隐私

技能包和仓库**不包含**任何图片、歌单、歌名、歌手名、排名或历史统计。
所有脚本只读你指定的目录，不联网、不上传。

`assets/` 下的示例文件是虚构数据，仅用于演示格式。
